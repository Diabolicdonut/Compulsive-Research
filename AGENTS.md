8. **Safe GitHub changes.** Work on a fresh feature branch, create reviewable commits and a PR, run CI, and merge only after checking all relevant preservation and deployment gates. Never force-push, roll back newer work, or mass-delete articles, research, validators or audit history. Parallel workers must compare current head before modifying shared checkpoint/roadmap files.
9. **Handoff in a durable form.** Each PR/accepted milestone must record starting and final SHA, specific changed files, validation that actually ran, milestone status/weight changes, accepted/pending warnings and the exact next resumable task. Do not claim a proposed PR or unfinished wave is accepted on `main`.

If an instruction conflicts with an older handoff, prefer the newest accepted GitHub `main` state and the full roadmap. A long-term vision change requires a documented roadmap amendment and, if necessary, a consciously approved progress rebaseline.
